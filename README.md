# 予舍 · AI 装修智能体协作平台

上传一张户型图，六位 AI 数字员工接力完成户型识别、二维施工图、同源 3D 模型、材料清单报价与工期，并做质检。业主确认后发布到接单市场，装修队投标，系统按真实报价、工期和资质匹配；业主选定后在线沟通、签约、分期履约。AI 只提供建议和草稿，确认、签署与付款都由人完成。

## 核心功能

- **户型到方案**：上传或手绘户型图，识别房间和门窗，生成二维图和可拖拽环绕的 3D 模型，并给出报价、工期和各房间效果图。
- **质检**：检查布局、报价合计和图片完整性；布局不合格会回退重做，超限后升级给老板裁决。
- **装修队匹配**：只按装修队的真实投标和资质档案排序，没有投标就不出匹配结果。
- **沟通与合同**：选定装修队后开放私聊；合同支持三方签署、阶段验收和分期结算，分演示与真实两种模式。
- **三类角色**：业主端、装修队端（`/contractor`）、老板控制台（`/boss`）。老板可一键创建临时演示装修队，体验竞标、匹配和沟通。

技术栈：Next.js 15、TypeScript、npm workspaces、PGlite + Drizzle、DeepSeek（识别与文字）、Agnes（效果图）。需要 Node.js 24，启动方法见[快速开始](#快速开始)。

> 边界：本仓库没有接入真实的电子签署或资金服务商，真实合同需要部署方自行接入，详见 [V2使用与部署说明](docs/V2使用与部署说明.md)。

- 顶部展示各阶段实际状态和一个当前操作入口，可定位到对应工作区。
- 六个工作区分别查看户型、设计、报价质检、匹配沟通、签约履约和岗位交接；切换时保留当前表单编辑。

## 业主与装修公司沟通

业主选定装修公司后，双方可在项目页/订单管理点击“沟通装修细节”，也可从登录导航进入 `/messages` 消息中心。支持文字交流、分页历史、未读/已读、幂等发送重试与约 3 秒轮询刷新。

会话按订单与公司隔离，未选中公司不能进入；更换承接方后原会话只读，重新选回原公司则继续原会话。普通平台账号不读取双方私聊。聊天不自动修改报价、合同、验收或付款。

新表与索引由现有数据库启动流程创建，无需清空数据。接口、开发记录和边界见 [沟通功能说明](docs/业主装企沟通功能.md)。图片/文件/语音、离线推送和 WebSocket 未实现；完整浏览器与小屏视觉验收待做。部署本轮源码后功能才会出现在生产网站，仓库上传不会自动替代服务器部署。

真实 Web 主链执行器在 `apps/web/lib/runner.ts`；`apps/worker` 为另行保留的 BullMQ 扩展骨架，不能仅凭其构建通过宣称外部队列闭环已完成。户型图片识别和效果图调用模型；画板、二维/3D、报价与 QA 包含规则实现，详见岗位说明。已用一张真实户型图跑过一次真实模型预演（DeepSeek 识别 + Agnes 效果图）：识别、设计、报价和 9 张效果图均成功，但质检因门窗识别随机波动出现布局告警，交付报告未达到“齐备”，详见 [开发进度](docs/开发进度.md) 的 2026-11-14 实测记录。效果图是风格参考，不是按户型图的施工效果图。成本效果仍待验证。

## 结构

```
apps/web        Next.js 15（业主端 / 装修队端 / 老板控制台 + REST/SSE API）
apps/worker     Agent 运行时（BullMQ 消费者 + 调度器 + 大模型客户端）
packages/shared 共享类型：交接协议、异常规则、Agent 图、红线动作
```

## 快速开始

```bash
npm install
cp .env.example apps/web/.env.local  # 填入服务端密钥、SESSION_SECRET 与老板账号
npm run dev                       # Next.js  → http://localhost:3000
```

需要 Node.js 24。当前线上仅运行 `apps/web`，它包含 API、PGlite 数据库和串行 Agent Runner。`apps/worker` 是尚未接入线上流程的独立骨架，不要与内嵌 Runner 同时当作生产任务执行器。当前部署无需 Redis、外置 PostgreSQL 或 OSS。

个人业主免费；企业只开放一人付基础会员 39 元/月。收到付款返回后查询服务端权益，生成购买入口本身不代表付款成功，不自动续费。其他套餐暂不开放。

生产启动与检查：

```bash
npm ci
npm run typecheck
npm test
npm run build
NODE_ENV=production npm run start -w apps/web -- -H 127.0.0.1 -p 3200
```

线上由 systemd 管理，前端需要 HTTPS 才能使用安全登录 Cookie。`IRENO_PGLITE_DIR` 和 `IRENO_UPLOAD_DIR` 应指向绝对路径并备份；不要在多个服务进程中打开同一个 PGlite 目录。大模型（默认 DeepSeek，由 `LLM_API_KEY` 等环境变量配置）负责识别，Agnes 负责图像，支付凭证只给服务端读取。邮箱未启用时手机号密码登录仍可使用。

`npm test` 使用临时数据库并在结束后清理。`scripts/acceptance.mjs`、`scripts/media-acceptance.mjs` 和 `scripts/browser-acceptance.cjs` 是本次隔离验收工具，不能直接对生产数据运行。`browser-acceptance.cjs` 自带隔离数据库和服务：`npm run build` 后运行 `node scripts/browser-acceptance.cjs --isolated-demo`，可用 `PLAYWRIGHT_CORE_PATH`、`CHROME_PATH`、`BROWSER_ACCEPTANCE_OUT` 指定 Playwright、Chrome 和输出目录；`acceptance.mjs` 与 `media-acceptance.mjs` 写死了服务器上的 `/opt/irenovation-remediation` 目录，换环境前需先改路径。`scripts/chain-acceptance.cjs` 同样自带隔离环境，用合成账号走“确认、发布、公司准入、投标、匹配、选定、合同工作台”这条主链并检查公司端、老板端、业主端页面：`npm run build` 后运行 `node scripts/chain-acceptance.cjs --isolated-demo`（端口 3323，可用 `CHAIN_ACCEPTANCE_OUT` 指定输出目录）。正向企业会员测试的模拟权益仅由验收服务通过 `node --require scripts/test-payments.cjs` 预加载，它只把支付服务的权益查询换成固定结果；生产服务禁止加载它。
