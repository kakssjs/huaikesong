## 业主与装修公司沟通

业主选定装修公司后，双方可在项目页/订单管理点击“沟通装修细节”，也可从登录导航进入 `/messages` 消息中心。支持文字交流、分页历史、未读/已读、幂等发送重试与约 3 秒轮询刷新。

会话按订单与公司隔离，未选中公司不能进入；更换承接方后原会话只读，重新选回原公司则继续原会话。普通平台账号不读取双方私聊。聊天不自动修改报价、合同、验收或付款。

新表与索引由现有数据库启动流程创建，无需清空数据。接口、开发记录和边界见 [沟通功能说明](docs/业主装企沟通功能.md)。图片/文件/语音、离线推送和 WebSocket 未实现；完整浏览器与小屏视觉验收待做。部署本轮源码后功能才会出现在生产网站，仓库上传不会自动替代服务器部署。

## 产品与交付

产品整体为 AI 装修智能体团队：调度、户型识别、设计与同源3D、报价工期、质检和施工方匹配协作推进交付，签约与履约是其中的后续环节。团队定位调整见 [说明](docs/团队定位调整说明.md)。

赛题对齐入口为 `/opc`（导航“团队与服务”），包含商业模式画布、六岗位说明、交付标准和演示流程；[参赛材料](docs/参赛交付材料.md) 可在页面下载。修改记录见 [赛题对齐与后续修改记录](docs/赛题对齐与后续修改记录.md)。调整页面材料后执行 `npm run opc:materials` 同步 Markdown 下载件。

项目页新增“本轮交付与人工复核”，检查最新任务、依赖更新、缺图、数字一致性及 QA。缺图可以保留部分成果展示，最终确认和新发布需成果齐备；补图或修改后可提交重新质检。确认绑定本轮 QA，旧确认不能自动沿用。业主与平台可通过 `/api/projects/:id/delivery?download=1` 下载交付 JSON。只读报告不会触发模型、自动确认或支付。

真实 Web 主链执行器在 `apps/web/lib/runner.ts`；`apps/worker` 为另行保留的 BullMQ 扩展骨架，不能仅凭其构建通过宣称外部队列闭环已完成。户型图片识别和效果图调用模型；画板、二维/3D、报价与 QA 包含规则实现，详见岗位说明。已用一张真实户型图跑过一次真实模型预演（DeepSeek 识别 + Agnes 效果图）：识别、设计、报价和 9 张效果图均成功，但质检因门窗识别随机波动出现布局告警，交付报告未达到“齐备”，详见 [开发进度](docs/开发进度.md) 的 2026-11-14 实测记录。效果图是风格参考，不是按户型图的施工效果图。成本效果仍待验证。

合同履约 V2 已实现：公司先确认、业主议价与版本重确认、三方签署、私有公章、合同下载、阶段验收与整改、入金/分期结算/退款、服务费及争议记录。新业务不再在签署时产生旧整单利润分成。操作和升级见 [V2使用与部署说明](docs/V2使用与部署说明.md)，接口见 [workflow API](docs/workflow-api.md)。

合同分“真实”和“演示”两种模式，默认是真实模式；只有启动服务时设置 `CONTRACT_MODE=demo`，新建的合同才使用演示签署和模拟资金，已有合同保持原模式。真实模式下的签署和资金只在带服务商回执时才记录。**本仓库没有接入任何电子签署或资金服务商**（只定义了适配器接口），所以真实合同目前无法完成签署和资金操作；页面上也只有演示合同的签署和资金按钮。正式接入需要部署方选定服务商并补上服务端取回执的环节，见部署说明。
完整方案见 [修改方案](docs/requirements-v2.md)，本轮追踪见 [赛题对齐与后续修改记录](docs/赛题对齐与后续修改记录.md)。

## 结构

```
apps/web        Next.js 15（业主端 / 装修队端 / 老板控制台 + REST/SSE API）
apps/worker     Agent 运行时（BullMQ 消费者 + 调度器 + 大模型客户端）
packages/shared 共享类型：交接协议、异常规则、Agent 图、红线动作
```

## 快速开始

```bash
npm install
cp .env.example apps/web/.env.local  # 填入服务端密钥、SESSION_SECRET 与老板账号
npm run dev                       # Next.js  → http://localhost:3000
```

需要 Node.js 24。当前线上仅运行 `apps/web`，它包含 API、PGlite 数据库和串行 Agent Runner。`apps/worker` 是尚未接入线上流程的独立骨架，不要与内嵌 Runner 同时当作生产任务执行器。当前部署无需 Redis、外置 PostgreSQL 或 OSS。

个人业主免费；企业只开放一人付基础会员 39 元/月。收到付款返回后查询服务端权益，生成购买入口本身不代表付款成功，不自动续费。其他套餐暂不开放。

生产启动与检查：

```bash
npm ci
npm run typecheck
npm test
npm run build
NODE_ENV=production npm run start -w apps/web -- -H 127.0.0.1 -p 3200
```

线上由 systemd 管理，前端需要 HTTPS 才能使用安全登录 Cookie。`IRENO_PGLITE_DIR` 和 `IRENO_UPLOAD_DIR` 应指向绝对路径并备份；不要在多个服务进程中打开同一个 PGlite 目录。大模型（默认 DeepSeek，由 `LLM_API_KEY` 等环境变量配置）负责识别，Agnes 负责图像，支付凭证只给服务端读取。邮箱未启用时手机号密码登录仍可使用。

`npm test` 使用临时数据库并在结束后清理。`scripts/acceptance.mjs`、`scripts/media-acceptance.mjs` 和 `scripts/browser-acceptance.cjs` 是本次隔离验收工具，不能直接对生产数据运行。`browser-acceptance.cjs` 自带隔离数据库和服务：`npm run build` 后运行 `node scripts/browser-acceptance.cjs --isolated-demo`，可用 `PLAYWRIGHT_CORE_PATH`、`CHROME_PATH`、`BROWSER_ACCEPTANCE_OUT` 指定 Playwright、Chrome 和输出目录；`acceptance.mjs` 与 `media-acceptance.mjs` 仍引用旧部署路径，不能直接使用。`scripts/chain-acceptance.cjs` 同样自带隔离环境，用合成账号走“确认、发布、公司准入、投标、匹配、选定、合同工作台”这条主链并检查公司端、老板端、业主端页面：`npm run build` 后运行 `node scripts/chain-acceptance.cjs --isolated-demo`（端口 3323，可用 `CHAIN_ACCEPTANCE_OUT` 指定输出目录）。正向企业会员测试的模拟权益仅由验收服务通过 `node --require scripts/test-payments.cjs` 预加载，它只把支付服务的权益查询换成固定结果；生产服务禁止加载它。

## 已实现

- [x] Monorepo（npm workspaces + TypeScript）
- [x] shared：TaskRecord 交接协议、异常规则表、HANDOFF_GRAPH、Agent 红线动作
- [x] shared：**2D→3D 重建管线**（`plan.ts`）——plan JSON（墙/门/窗/房间）为唯一事实源，`generatePlanGeometry` 按面积自动布局、`planFromRects` 按用户手绘/识别矩形建模，`planToSvg` 输出二维施工图，Scene3D 同源拉伸 3D
- [x] worker：大模型客户端骨架、8 个 Agent 的 prompt/工具白名单、BullMQ 消费者（重试/降级/升级骨架）
- [x] web：Next.js 15 首页 + /api/health + PGlite/Drizzle 数据层
- [x] 业主端设计包：户型识别 → 二维装修图（墙/门/窗/尺寸）→ 3D 交互模型（拖拽环绕/俯视）→ 材料清单+报价+工期 + Agnes 效果图（可对话修改）
- [x] **户型图输入（用户给图）**：上传户型图 / 画板手绘（框房间+自由画笔）→ Agnes 图生图生成标准平面图（i2i 队列）→ 大模型视觉识别房间矩形 → 按二维图生成 3D；结果持久化（kind=floorplan，覆盖式 upsert）
- [x] **各房间渲染图（有几个生成几个）**：以识别/手绘房间为准（kind=floorplan rects 优先，Agent 房间兜底），全量生成不设上限，3 张并发 + 实时进度；对话改图即改即存（upsert）
- [x] 老板控制台（/boss，实时数据）：审批队列（★红线人工确认）、任务记录（Task Record）、成本看板（Token/图像按 Agent 汇总）、订单（第一单闭环）
- [x] 装修队端（/contractor）：注册、资质提交、应标；老板人工资质审核（★ Agent 不代为认证）
- [x] **匹配流程（确认 → 发布 → 等投标 → 匹配）**：核心链智能体逐个执行（户型识别→二维设计→报价工期→质检交付，matcher 不入链）；业主最终确认后自动发布接单市场，**等待装修公司发布数据（投标）**，投标到达触发匹配智能体「小桥」——按真实投标（报价/工期贴合）+ 公司资质档案（人工审核状态/风格专长/服务范围/执照）打分匹配；无投标不出匹配结果，业主端显示等待状态流（发布·竞标·匹配四步）
- [x] 数字员工体系：花名册（小调/小测/小设/小算/小桥/小检）+ 卡通人物头像（Agnes 文生图统一风格，SVG 兜底）+ 执行日志任务交接链（fromAgent→toAgent）
- [x] 业主最终确认（人工动作）→ 自动发布接单市场 → 装修公司投标 → 智能体匹配推荐 → 业主选定 → 公司及业主确认报价 → 三方版本化合同、签署与分期履约（Agent 不代人确认或签署；演示合同为演示签署，真实合同待接入服务商）
- [x] **异常处理落地（EXCEPTION_RULES）**：调度器按规则分派 retry（≤N 次重试）/ degrade（降级交付不断链）/ escalate_boss（升级老板裁决）/ reask_user（反问用户补充）；任务状态扩展 escalated / waiting_user；业主端异常横幅（补充按钮 → resume 续跑）、老板端审批队列按规则名展示
- [x] **QA 质检实现（小检）**：布局规则（墙/门洞/ForgeFloor 告警）+ 报价核对（明细合计=总价、与确定性基准偏离≤30%，超差按红线升级老板）+ 图片完整性（缺失降级不阻塞）；几何不过回退设计智能体 ≤2 轮，超限升级（匹配质检由匹配智能体在投标后单独把关）
- [x] **我的项目删除**：业主工作台/项目页两级确认删除，级联清理任务/结果/订单/投标/合同 + 户型图文件
