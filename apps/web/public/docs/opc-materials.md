# 予舍｜商业模式画布、岗位说明与演示材料

版本日期：2026-11-14。产品定位为 AI 装修智能体团队。本文描述当前方案；外部模型效果、成本、获客与收入数据没有实测的部分均不作完成承诺。

## 一、商业模式画布

### 目标客户

有住宅装修需求的业主，以及希望获得匹配项目的装修公司。初期从单一城市和熟悉的装修场景验证。

### 客户痛点

需求难表达、方案与报价难对齐、公司报价难比较，确认与履约资料分散。痛点强度仍需访谈验证。

### 价值主张

把户型、方案、费用依据和施工方比较串在同一项目中，让业主拿到可复核的成果再作决定。

### 交付内容

房间数据、二维与同源 3D、效果图、报价工期、规则质检和真实投标比较；确认后衔接合同及分期记录。

### 定价与收入

当前方案为业主免费使用设计能力；装修公司按合同约定的阶段结算承担服务费。默认演示费率 3%，具体以签约条款为准；会员服务独立列示。

### 成本结构

模型与图像调用、存储及部署、获客、人工资料审核、方案复核和履约协调。单项目成本与毛利尚待实测。

### 获客渠道

拟通过装修内容、业主转介绍、本地装企合作及案例体验获客。渠道转化与获客成本属于待验证假设。

### 关键协作

业主提供并确认资料，装企确认施工与报价，平台组织记录和协调；正式签署、资金和争议服务需要对应外部服务方。

### 壁垒与验证

拟积累经授权的方案与报价修正记录、区域价格维护及履约反馈。数据规模、交付效率与复购效果尚未证实。

## 二、岗位说明书

主讲岗位建议候选为小测（图片户型识别路径）：具有真实模型入口，能将图片交接成可复核房间与几何数据。最终选用前必须完成真实模型预演；没有密钥或模型不可用时，不把人工画板路径称为模型成功。本轮未作“最稳定岗位”结论。

### 小调 · 调度总管

- 输入：需求、任务状态与异常规则
- 执行方式：按既定流程创建交接任务，重试或转人工待办。
- 交付：真实任务流、状态和异常记录
- 人工介入：平台处理超限与红线异常。
- 验收标准：交接有来源和去向；异常不伪装为成功。

### 小测 · 户型识别师

- 输入：清晰户型图，或业主在画板标注的房间，以及申报面积
- 执行方式：图片路径调用识别模型；画板路径读取人工标注，再由程序统一换算空间数据。
- 交付：房间名称、面积、几何数据与识别来源
- 人工介入：业主核对房间及面积；尺寸需现场量房。
- 验收标准：有真实来源、有效房间和可核对面积；低置信度先补资料。

### 小设 · 设计师

- 输入：户型空间数据、风格与需求
- 执行方式：程序生成二维和同源 3D，图像模型生成房间效果图。
- 交付：二维图、3D 场景与效果图
- 人工介入：业主确认方案；涉及施工安全需专业人员复核。
- 验收标准：空间数据保持一致；缺失图片明确标出并支持补生成。

### 小算 · 报价师

- 输入：房间面积、风格与已采集参考价格
- 执行方式：按规则计算费用、价格来源和工期估算，不宣称为独立模型推理。
- 交付：分项数量、单价、金额、总价与阶段工期
- 人工介入：业主与装企核对工程量、范围及最终报价。
- 验收标准：数量乘单价与金额一致、明细合计与总价一致、阶段工期合计一致。

### 小检 · 交付质检员

- 输入：布局、报价与图片结果
- 执行方式：程序执行几何、金额和完整性规则检查；问题回退或转人工。
- 交付：通过项、问题清单与复核事项
- 人工介入：规则质检不能代替现场施工验收。
- 验收标准：失败项可见；回退超限转人工；不能把旧质检当作本轮通过。

### 小桥 · 施工方匹配

- 输入：业主发布的项目、实际投标及公司资料
- 执行方式：规则筛选真实投标，再尝试模型排序与说明；模型不可用时明确使用规则结果。
- 交付：候选比较、依据与推荐理由
- 人工介入：平台审核资质，业主决定承接方与价格。
- 验收标准：没有实际投标就等待；推荐来自实际候选，说明匹配来源。

### 签约与履约的接续边界

签约辅助接续已确认的方案与报价，提供规则草案和可选模型复核。三方确认、签署、用章、施工验收和资金决定由有权限的人操作。合同分真实与演示两种模式：真实合同的签署和资金只在电子签署或资金服务商返回回执时才记录，每笔拨付和退款先经平台复核，平台可与资金服务商对账，已签合同只能通过三方签署的补充协议变更。仓库提供这套流程和适配器接口，并用仅供测试的替身服务商做过隔离验收，但没有接入任何真实的电子签署或资金服务商，所以真实合同在部署方接入服务商之前仍不能完成签署和资金操作。演示合同（启动时设置 CONTRACT_MODE=demo）使用演示签署和模拟资金，仅用于展示流程。正式电子签署、实名核验、真实资金托管与出款未接入。

## 三、5 分钟路演脚本

| 时间 | 内容 | 操作与证据 |
|---|---|---|
| 0:00–0:40 | 说明客户与收费 | 展示商业模式画布，讲清业主价值、装企付费条件及当前模拟边界。 |
| 0:40–1:10 | 介绍团队与主讲岗位 | 展示六岗位分工；建议以图片户型识别为主讲候选，现场前须先验证模型可用。 |
| 1:10–2:30 | 执行关键任务 | 上传合成户型资料并执行。若改用人工画板，明确标为人工输入与规则执行；预置结果不能称为现场生成。 |
| 2:30–3:40 | 核对交付与人工待办 | 查看本轮交付面板、任务编号、输入来源、图纸、报价与质检；下载真实保存成果。 |
| 3:40–4:30 | 衔接业务闭环 | 用同一项目说明方案确认、真实投标与承接；展示合同样例须用演示模式启动，并标明演示签署与模拟结算。 |
| 4:30–5:00 | 展示结果与限制 | 说明本轮完成、尚未验证项和赛内新增；没有实测的耗时与成本不报数字。 |

### 2 分钟问答准备

- AI 做了什么？按真实路径解释图片识别与图像模型；调度、二维/3D、报价、QA 中的规则如实说明。
- 谁付费？业主免费设计，装修公司按约定阶段结算承担服务费；会员独立，不等于已验证收入。
- 人为什么需要介入？确认需求、价格、主体授权、签署和现场验收。
- 效率与成本如何？提供实测样本；暂未测量就明确待测，不能填推算数字冒充结果。

## 四、演示与备用流程

1. 使用明确标记的合成户型与项目，准备可访问的模型配置，先完成一次真实预演。
2. 主演示从真实输入开始，显示实际任务编号与本轮交付面板；成果仅“可复核”，不自动称为业主已接受。
3. 缺输入时补资料；模型超时/失败时按真实提示重试或转人工，不能提前写入 done。
4. 模型不可用时展示已保存成果或录像，注明生成时间和“备用历史结果”；人工画板路径注明人工标注。
5. 合同样例演示时须以 CONTRACT_MODE=demo 启动服务，并注明合成主体、演示签署和模拟资金；默认的真实合同在真实服务商接入前无法完成签署，不能用于现场演示签署。
