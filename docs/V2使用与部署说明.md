# 予舍 V2 使用与部署说明

## 已完成的业务流程

保留户型识别、设计、3D、报价和投标；补回业主竞标表的选定公司入口。

选定承接公司后，业主项目页、公司订单页、平台订单页均可进入同一个合同履约工作台：公司先确认，业主接受或议价；修改后重新确认；三方资料补齐后生成草案、冻结并逐方演示签署。公司保存自己的签约资料与公章，每次用章均需明确授权。已签正文只读，下载件不随后续交易改变。

施工方按阶段提交资料，业主通过或驳回、整改重提。模拟入金后，满足验收、余额及争议条件才能模拟拨款。手续费按合同费率计算并记录，重复请求不会重复拨款；争议限制阶段出款，退款保留已验收但未结算的款项。

经独立处理结果明确解除某个未结算阶段时，平台在处理安排选择解除，该阶段不再允许施工提交或拨款，原验收和处理记录保留，相关未付金额解除保留后可申请模拟退款。签名、公章在签署件中使用绑定合同编号和版本的派生图，不能将原始公章文件作为共享素材。

签约专员提供规则草案、缺项和金额校验；主动点击 AI 辅助复核且配置了现有模型服务后，才进行只读模型复核。未配置时明确显示模型未调用，不影响规则草案。模型不能改合同金额或执行签署、验收和付款。

## 操作顺序

1. 公司在私有签约资料中填写名称、登记资料、授权代表、联系方式，并上传有权使用的公章。
2. 业主选择投标公司，在合同工作台补齐自己的资料和项目面积口径；平台填写自己的签约主体资料。
3. 公司检查金额、范围、工期与阶段表，确认；业主接受或提出议价。议价后由公司重新确认、业主最终接受。
4. 生成规则草案，清理缺项和错误，核对附件与服务费，冻结版本。
5. 三方分别输入签署人，上传本人签名或手写；公司确认本次用章。所有页面持续显示演示签署标识。
6. 业主模拟入金；公司提交阶段证据；业主验收或驳回。验收后业主可申请模拟阶段拨款，查看服务费及流水。
7. 有争议时提交阶段和证据，平台登记独立处理方与依据；相关受限资金不能直接拨付。已签正文变更目前安全阻止，需另行办理补充协议。

## 运行与升级

要求 Node.js 24。在项目根目录运行 npm ci，然后配置 apps/web/.env.local，保留原部署中的模型、登录、邮箱等配置，不使用演示口令作为线上口令。

验证命令为 npm test、npm run typecheck、npm run build。生产启动命令为 npm run start -w apps/web -- -H 127.0.0.1 -p 3200，由反向代理提供对外访问。

升级前备份现有数据库、上传目录和环境配置。IRENO_PGLITE_DIR 与 IRENO_UPLOAD_DIR 继续指向原部署的绝对路径，新表通过增量DDL建立。PGlite只由单个应用进程打开；停止旧实例后再启动新实例。旧合同及旧分成记录保留，新流程不自动生成旧利润10%分成。已签或已有资金历史的项目不允许直接硬删。

已有会员服务保留为独立业务。新投标按默认3%合同服务费预估，实际以签约版本为准；仅成功的模拟阶段结算产生模拟费用，会员收款不计作工程款。

## 本地隔离验收

本地测试前设置 RUNNER_ENABLED=false，并为 IRENO_PGLITE_DIR、IRENO_UPLOAD_DIR 指定专用新目录。清空测试进程的外部模型和支付密钥，防止既有任务runner或支付权益检查调用真实服务。

scripts/seed-workflow-demo.cjs --isolated-demo 仅允许非生产环境和全新绝对数据库目录，拒绝覆盖已有数据库。它创建一个合成项目及测试账号，不调用外部AI或真实支付。执行时用 node 运行该脚本。

合成业主账号19900000001、公司账号19900000002、无关测试账号19900000003，测试口令均为DemoOnly2026!。这些账号只存在于专用测试库，不能用在正式服务。平台账号由该测试进程的BOSS_PHONE/BOSS_PASSWORD单独配置；HTTP验收脚本默认使用19900000000及DemoBossOnly2026!。SESSION_SECRET请单独配置测试值，HTTP本地测试设置COOKIE_SECURE=false。

先运行种子脚本并结束该进程，再启动指向同一测试目录的Next服务，仅监听127.0.0.1。默认3301端口可执行 node scripts/workflow-http-smoke.cjs；其他端口用WORKFLOW_TEST_URL指定。该脚本只允许回环地址，需新种子数据，重复运行应换新测试库。不要直接对线上运行旧acceptance、AI-e2e和payment-smoke脚本。

## 正式服务接入边界

签名图片、公章和资金流水当前是可追踪演示，不是已接入可靠电子签署、身份认证或第三方资金托管。正式服务需要实际合同主体、经审查模板、适用电子签署及证据服务、适用银行或持牌支付机构的资金产品、对账与退款接入。

复杂补充协议编辑、多实例数据库及正式第三方回调没有伪装为已实现。外部参考图链接会提示远程内容未冻结；上传的受限图片才能进入版本快照。

本次只修改本地源码，未更新远程网站。交付源码包不含node_modules、Git历史、构建缓存、数据库、私有上传或实际.env配置。
