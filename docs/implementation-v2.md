# 予舍合同履约功能实施计划

依据：同目录 requirements-v2.md。

约束：保留现有设计、3D和投标流程；只清理赛事宣传文字，保留正常模型接口和产品目录。使用现有身份及归属校验；签署与资金明确为演示；不得调用真实付款或生成公章。旧合同入口不能绕过新确认与签署条件。存储变更兼容已有数据，不覆写旧合同。（2026-11-14 补充：此为 V2 当时的约束。之后合同加入“真实”模式，默认真实、`CONTRACT_MODE=demo` 保留演示，见 `docs/workflow-api.md`；真实模式只接受服务商回执，仓库未接入任何服务商。）

1. 清除中英文首页、页脚及说明的旧参赛标识。
2. 建立可测试合同工作流及持久化API：公司先确认、业主议价、版本冻结、三方签署、合同导出、阶段验收、模拟资金、服务费、争议冻结和退款。
3. 将同一份合同工作台接入业主、公司和平台页面，补公司签约资料与公章上传，所有操作遵守服务端角色和版本检查。
4. 接入签约专员草案与校验交付物，补首页岗位表达和业务说明，保留已实现的其他智能体。
5. 进行状态、金额、权限和并发回归，运行完整测试、类型检查和生产构建，做本地页面和API验收。
6. 独立代码审查并修复重要问题，整理操作说明与修改源码压缩包。

任务依赖：2定义工作流与API接口供3消费；4使用2的合同快照与校验；5覆盖2和3，6依赖全部验证。

决策：源ZIP无Git仓库，在新解压目录初始化feature/contract-workflow-v2分支保存原始基线；不修改线上服务器。真实电子签署和支付托管作为明确的后续接入项。
