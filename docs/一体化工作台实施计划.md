# 一体化工作台实施计划

日期：2026-11-15。基于仓库 `3b45cf4`；用户已认可“一个项目工作台，由小调串联六个岗位”的方案并要求实施。

## 本轮范围

沿用现有 Next.js、任务调度、交付报告和订单数据。顶部展示从需求到签约履约的完整流程；小调汇总真实当前状态、阻塞事项及一个主入口；成果按户型、设计、报价质检、匹配沟通、履约和交接记录分区查看。交接卡显示输入、成果、真实任务编号及交接状态。

选择保留现有业务模块并调整工作台组织方式。只增加岗位名称或固定聊天动画无法说明真实协作；重写调度及合同资金流程会扩大协作冲突，本轮不采用。

## 实施顺序

1. 实现可测试的工作台状态汇总：以本轮交付报告为准，识别过期成果、人工补充、失败、待确认、投标、已选公司和签约入口；历史失败不得覆盖本轮结果。
2. 增加全流程导航、小调摘要、真实成果交接卡和单一主入口。没有实际任务时展示等待交接，不宣称已执行。
3. 将现有模块整理进工作区，切换时保留输入及编辑状态；增加空状态与定位；保留既有业务接口和确认操作。
4. 验证状态回归、类型检查、生产构建及桌面/手机浏览器流程，更新开发进度和 README。

## 边界和验证重点

- 不修改签署、资金适配器、合同业务规则、数据库及相关 API；履约区嵌入现有工作台。
- 业主选定装修公司后才开放原有私密沟通；未选择时只展示等待提示。
- 小调摘要由真实记录归纳，不新增模型调用，不代表自动做出人工决定。
- 投标和订单信息加载失败时不能当作“尚未发布”。
- 上游更新后优先提示修复本轮交付；已有订单及沟通记录仍可访问。
- 验证：无任务、运行中、人工待办、历史失败后成功、上游重跑、旧确认、无投标、匹配失败/重跑、已选公司、已签约；手机导航无横向溢出；分区切换、主入口定位和 3D 保持可用。

## 后续阶段

需求变更单、影响分析、自动重跑相关岗位、成果版本差异和沟通摘要转待办尚未在本轮实现。聊天内容不会自动修改价格、方案或合同；有明确确认记录后再设计这些功能。
