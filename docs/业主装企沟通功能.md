# 业主与装修公司沟通功能｜设计与实施记录

日期：2026-11-14。用户已确定：**业主选定装修公司后才开放双方沟通**。

## 功能范围

本版提供项目关联的文字会话、历史消息、未读提示、发送失败重试和约 3 秒轮询刷新。业主从项目页进入，承接公司从订单管理进入，双方也可从导航进入消息中心。

会话绑定订单和对应公司，不按全站账号任意私信。服务端检查当前登录身份和真实承接关系；其他业主和未参与该会话的公司、普通平台账号不能进入双方会话。选定关系变化后，原会话仅保留给原参与方阅读，新承接公司建立自己的独立会话，不继承原公司的聊天。同一订单重新选回原公司时继续原有会话，保留历史，不另建空会话。

消息是沟通记录，不自动修改报价、合同、验收或付款状态。对价格、材料和施工范围的正式变更仍应在原确认/合同流程中处理。

第一版不包含图片/文件/语音、视频通话、离线推送或 AI 读取聊天。需要这些能力时再扩展；当前不把轮询称为 WebSocket 实时通讯。

## 数据与接口

- `project_conversations`：订单、业主、公司、参与方显示名快照、各自已读游标、更新时间；同订单与同公司唯一。
- `conversation_messages`：会话、真实发送人、正文、时间、客户端发送键；同发送键重试不产生重复消息，不同正文复用键返回冲突。
- `POST /api/orders/:id/conversations`：当前业主或选中公司进入会话；不能通过客户端指定另一公司伪造承接关系。
- `GET /api/conversations`：仅列本人的会话及未读数。
- `GET/POST /api/conversations/:id/messages`：本人会话的分页历史与发送；正文去首尾空白后 1～2000 字。
- `POST /api/conversations/:id/read`：仅将实际已展示到的消息标记已读；游标只前进，不会把之后到达的消息一并读掉。
- 删除可删除项目时，其订单会话与消息随订单级联；已有合同/履约历史的删除保护继续生效。

## 重点检查

未选中公司不能以公开订单浏览权限读取聊天；参与方 ID 不相信浏览器；旧公司只读；已读必须针对同一会话消息；发送重试不重复；轮询不覆盖输入或其他会话；正文按纯文本展示，不执行用户 HTML。
